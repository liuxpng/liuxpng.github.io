计算机如何理解文本？这是自然语言处理的核心问题。本文将从最基础的概念讲起，帮助你理解文本向量化的原理。

## 为什么需要向量表示

### 计算机只认识数字

计算机的本质是进行数学运算，它无法直接处理文字。当我们输入"今天天气真好"时，计算机看到的是一串编码（如 UTF-8），但这些编码只是用来**显示**文字，并不能表达文字的**含义**。

```
人类看到：今天天气真好
计算机看到：E4BB8A E5A4A9 E5A4A9 E6B094 E79C9F E5A5BD（UTF-8 编码）
```

这些编码无法告诉计算机：
- "今天"和"今日"意思相近
- "天气好"和"晴朗"表达类似含义
- "今天天气真好"是一句正面评价

### 向量：让文本可计算

**向量**是一组有序的数字，例如 `[0.5, -0.3, 0.8]`。

如果我们能把文本转换成向量，就可以：

| 需求 | 向量操作 |
|------|---------|
| 判断两句话是否相似 | 计算两个向量的距离 |
| 对文档进行分类 | 用向量训练分类器 |
| 搜索相关内容 | 找距离最近的向量 |

这就是**文本向量化**的意义：把文字转换成数字，让计算机能够"理解"和处理文本。

## 最简单的方法：词袋模型

### 基本思想

**词袋模型（Bag of Words）** 是最直观的向量化方法：统计每个词出现的次数。

想象你有一个袋子，把文章里的词一个个丢进去，最后数一数每个词有多少个。

### 具体步骤

**第一步：建立词表**

假设我们有两个句子：
- 句子 A："我 喜欢 吃 苹果"
- 句子 B："我 喜欢 吃 香蕉"

把所有出现过的词汇整理成一个列表（词表）：

```
词表：[我, 喜欢, 吃, 苹果, 香蕉]
位置：  0    1    2    3     4
```

**第二步：统计词频**

对每个句子，统计词表中每个词出现的次数：

```
句子 A："我 喜欢 吃 苹果"
向量 A：[1,   1,   1,   1,    0]
        我   喜欢  吃  苹果  香蕉

句子 B："我 喜欢 吃 香蕉"
向量 B：[1,   1,   1,   0,    1]
        我   喜欢  吃  苹果  香蕉
```

现在，两个句子都变成了向量！

### 计算相似度

有了向量，就可以计算两个句子的相似度。最常用的方法是**余弦相似度**：

```
余弦相似度 = (A·B) / (|A| × |B|)

A·B = 1×1 + 1×1 + 1×1 + 1×0 + 0×1 = 3
|A| = √(1² + 1² + 1² + 1² + 0²) = 2
|B| = √(1² + 1² + 1² + 0² + 1²) = 2

相似度 = 3 / (2 × 2) = 0.75
```

0.75 表示两个句子比较相似（1 表示完全相同，0 表示完全无关）。

### 其他相似度计算方法

除了余弦相似度，还有其他常用方法：

| 方法 | 公式 | 特点 |
|------|------|------|
| **余弦相似度** | A·B / (\|A\| × \|B\|) | 只看方向，不看长度。值域 [0, 1]（非负向量）或 [-1, 1] |
| **欧氏距离** | √Σ(Ai - Bi)² | 绝对距离，值越小越相似。受向量长度影响 |
| **点积** | Σ(Ai × Bi) | 计算最快。向量归一化后等价于余弦相似度 |

**如何选择？**

- **文本相似度**：优先用余弦相似度（不受文本长度影响）
- **大规模检索**：用点积（计算快），但需要先对向量归一化
- **聚类分析**：可以用欧氏距离

对于入门学习，理解余弦相似度就够了——它是文本检索中最常用的方法。

### 词袋模型的问题

虽然简单，但词袋模型有明显的缺陷：

**问题 1：忽略词的重要性**

```
句子："的 是 在 人工智能"
```

"的"、"是"、"在"这些词几乎在每个句子都会出现，它们的重要性和"人工智能"一样吗？显然不是。但词袋模型会给它们相同的权重。

**问题 2：忽略词序**

```
句子 A："狗 咬 人"
句子 B："人 咬 狗"
```

这两个句子意思完全不同，但词袋模型会认为它们一模一样（向量完全相同）。

**问题 3：无法理解语义**

```
查询："退货政策"
文档："我们支持 7 天无理由退款"
```

"退货"和"退款"意思很接近，但词袋模型认为它们是完全不同的词，无法匹配。

## 改进方案：TF-IDF

### 核心思想

**TF-IDF（Term Frequency-Inverse Document Frequency）** 解决了词袋模型"忽略词的重要性"的问题。

核心思想很简单：
- 一个词在**当前文档**中出现越多，越重要（TF）
- 一个词在**所有文档**中出现越少，越重要（IDF）

换句话说：如果一个词只在少数文档中出现，但在当前文档中出现多次，那它对当前文档特别重要。

### TF：词频

**TF（Term Frequency）** 表示一个词在当前文档中出现的频率。

```
TF = 该词在文档中出现的次数 / 文档的总词数
```

例如，文档有 100 个词，"机器学习"出现了 5 次：

```
TF("机器学习") = 5 / 100 = 0.05
```

### IDF：逆文档频率

**IDF（Inverse Document Frequency）** 衡量一个词的稀有程度。

```
IDF = log(文档总数 / 包含该词的文档数)
```

假设有 10000 篇文档：

| 词 | 出现在多少文档 | IDF |
|---|-------------|-----|
| 的 | 10000（几乎所有） | log(10000/10000) = 0 |
| 机器学习 | 100 | log(10000/100) = 2 |
| 量子纠缠 | 10 | log(10000/10) = 3 |

可以看到：
- "的"这种常见词，IDF 接近 0，说明它没有区分度
- "量子纠缠"这种专业词，IDF 很高，说明它很有区分度

### TF-IDF 计算

最终的权重是两者相乘：

```
TF-IDF = TF × IDF
```

**实际例子**：

假设在一篇关于机器学习的文章中：

| 词 | TF | IDF | TF-IDF |
|---|-----|-----|--------|
| 的 | 0.08 | 0 | 0 |
| 机器学习 | 0.05 | 2 | 0.10 |
| 神经网络 | 0.03 | 2.5 | 0.075 |

"的"虽然出现最多，但 TF-IDF 权重为 0；"机器学习"虽然出现次数不是最多，但权重最高。

### TF-IDF 的实际应用

TF-IDF 被广泛用于：

1. **搜索引擎**：早期搜索引擎用 TF-IDF 对网页排序
2. **关键词提取**：找出文档中 TF-IDF 最高的词
3. **文档相似度**：用 TF-IDF 向量计算文档之间的相似度

## BM25：TF-IDF 的进化版

**BM25（Best Matching 25）** 是 TF-IDF 的改进版本，由 Robertson 等人在 1994 年提出，"25"表示这是 BM 系列算法的第 25 个版本。

### 为什么需要 BM25

TF-IDF 还有一些问题：

**问题 1：词频没有上限**

如果一个词出现 100 次，TF 是出现 10 次的 10 倍。但实际上，一个词出现 100 次和 10 次，重要性差距没那么大。

**问题 2：没考虑文档长度**

长文档天然包含更多词，TF 会偏高，这不公平。

### BM25 的改进

**BM25** 在 TF-IDF 基础上做了两个改进：

**改进 1：词频饱和**

```
BM25 的 TF 部分 = (词频 × (k1 + 1)) / (词频 + k1)
```

其中 **k1** 是一个可调参数，控制词频饱和的速度：
- k1 越大，高词频的词权重越高（饱和越慢）
- k1 越小，词频的影响越快趋于平缓
- 常用默认值：**k1 = 1.2**（Elasticsearch 默认）或 2.0

当 k1=1.2 时：
- 词频=1 → 得分≈1.1
- 词频=10 → 得分≈1.9
- 词频=100 → 得分≈2.1

词频再高，得分也趋于一个上限，避免了某个词出现过多次导致权重爆炸。

**改进 2：文档长度归一化**

问题：长文档天然包含更多词，词频会偏高，这对短文档不公平。

BM25 引入文档长度因子：

```
长度因子 = 1 - b + b × (文档长度 / 平均文档长度)
```

其中 **b** 是长度归一化参数：
- b = 0：完全不考虑文档长度
- b = 1：完全按长度比例调整
- 常用默认值：**b = 0.75**（Elasticsearch 默认）

**效果**：
- 文档比平均长 → 长度因子 > 1 → 词权重降低
- 文档比平均短 → 长度因子 < 1 → 词权重提高

这样，一个词在 100 字的短文档中出现 3 次，可能比在 10000 字的长文档中出现 3 次更重要。

### BM25 的地位

BM25 是目前最成熟的传统文本检索算法：

- Elasticsearch 的默认排序算法就是 BM25
- 很多搜索系统至今仍在使用 BM25
- 在 RAG 系统中，BM25 常与向量检索结合使用（混合检索）

## 稀疏向量的根本局限

词袋、TF-IDF、BM25 都属于**稀疏向量**方法：

```
词表大小：50000 个词
向量维度：50000 维
大部分维度的值：0
```

无论怎么改进权重计算，稀疏向量都有一个根本问题：**无法理解语义**。

### 同义词问题

```
查询："手机"
文档："智能电话的发展历程"

稀疏向量：无法匹配（"手机" ≠ "智能电话"）
```

### 一词多义问题

```
"苹果很好吃" → "苹果"是水果
"苹果发布新手机" → "苹果"是公司

稀疏向量：无法区分，两个"苹果"的向量完全相同
```

### 语义相似问题

```
"今天天气真好" 和 "今日阳光明媚"

人类知道这两句话意思相近，但稀疏向量会认为它们差别很大（几乎没有共同的词）。
```

要解决这些问题，我们需要一种全新的方法：**密集向量（Dense Embedding）**。

---

## 总结

本文介绍了文本向量化的基础方法：

| 方法 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| 词袋模型 | 统计词频 | 简单直观 | 忽略词的重要性 |
| TF-IDF | 词频 × 逆文档频率 | 区分词的重要性 | 无法处理词频过高 |
| BM25 | TF-IDF + 词频饱和 + 长度归一化 | 效果最好的稀疏方法 | 无法理解语义 |

这些方法的共同问题是：只能匹配**字面相同**的词，无法理解**语义相似**的概念。
