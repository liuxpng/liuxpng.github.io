上一篇文章我们了解了稀疏向量的局限：无法理解语义。本文将深入讲解**密集向量（Embedding）**的原理，回答一个核心问题：为什么语义相似的文本，向量距离会更近？

## 从稀疏到密集

### 稀疏向量的问题

回顾一下稀疏向量：

```
词表大小：50000 个词
"苹果"的向量：[0, 0, 0, ..., 1, ..., 0, 0]
                         ↑
                    第 3847 位是 1，其他都是 0
```

这种向量有两个问题：
1. **维度太高**：词表有多大，向量就有多少维
2. **没有语义**：每个维度只表示"是否出现某个词"，无法表达词与词之间的关系

### 密集向量的特点（Dense Vector）

```
维度：768 维（固定，远小于词表大小）
"苹果"的向量：[0.12, -0.34, 0.56, 0.78, -0.23, ...]
              每个维度都有值，不再是 0/1
```

**关键区别**：

| 特性     | 稀疏向量             | 密集向量         |
| -------- | -------------------- | ---------------- |
| 维度     | 词表大小（如 50000） | 固定值（如 768） |
| 值       | 大部分是 0           | 所有维度都有值   |
| 生成方式 | 统计词频             | 神经网络学习     |
| 语义     | 无                   | 有               |

最神奇的是：**语义相似的词，密集向量距离也近**。

```
"苹果"的向量 ≈ "香蕉"的向量（都是水果）
"苹果"的向量 ≠ "汽车"的向量（完全不同类别）
```

为什么会这样？这就需要理解 Embedding 背后的核心原理：**分布假设**。

---

## 核心原理：分布假设

### 什么是分布假设

**分布假设（Distributional Hypothesis）** 是语言学中的一个重要理论：

> 经常出现在相似上下文中的词，语义也相似。

这句话看起来简单，但它是整个 Embedding 技术的理论基础。

### 直观理解

让我们看几个例子：

**例子 1：水果类**

```
"我喜欢吃___"
    苹果
    香蕉
    橙子
    西瓜
```

这些词都能填入同一个空位，说明它们经常出现在相似的语境中，所以语义相近。

**例子 2：动物类**

```
"___在草地上奔跑"
    狗
    猫
    马
    兔子
```

这些词也能填入同一个空位，说明它们语义相近。

**例子 3：跨类别**

```
"苹果"能出现的语境：我喜欢吃___、___很甜、___是一种水果
"汽车"能出现的语境：我开着___、___很快、___是一种交通工具
```

"苹果"和"汽车"几乎不会出现在相同的语境中，所以它们语义不相似。

### 分布假设的数学表达

分布假设告诉我们：

```
如果 词A 和 词B 经常出现在相似的上下文中
那么 向量(A) 应该接近 向量(B)
```

这就是神经网络需要学习的目标：让相似语境的词，向量也相似。

---

## Word2Vec：让分布假设变成现实

### 什么是 Word2Vec

**Word2Vec** 是 Google 在 2013 年发布的模型，它第一次大规模证明了：可以用神经网络学习词的密集向量，而且这些向量真的能捕捉语义关系。

Word2Vec 有两种训练方式：

| 方式          | 全称                    | 训练目标             | 特点                 |
| ------------- | ----------------------- | -------------------- | -------------------- |
| **CBOW**      | Continuous Bag of Words | 根据周围词预测中心词 | 训练快，适合高频词   |
| **Skip-gram** | -                       | 根据中心词预测周围词 | 效果更好，适合低频词 |

我们重点讲更常用的 **Skip-gram**。

### Skip-gram 的核心思想

**训练目标**

Skip-gram 的目标非常简单：给定一个词，预测它周围可能出现哪些词。

```
句子："我 喜欢 吃 苹果 和 香蕉"

中心词：苹果
周围词（窗口大小=2）：吃、和

训练目标：给定"苹果"，预测出"吃"和"和"可能在它附近
```

**训练数据：自监督学习**

Word2Vec 的巧妙之处在于：不需要人工标注哪些词相似。训练数据就是普通的文本（如维基百科、新闻），训练样本自动从文本中提取：

```
句子："我 喜欢 吃 苹果"

自动提取的训练样本（中心词, 周围词）：
  (苹果, 吃)     ✓ 正样本（真实出现在一起）
  (苹果, 喜欢)   ✓ 正样本
  (苹果, 汽车)   ✗ 负样本（随机采样，没一起出现过）
```

这种方法叫**自监督学习**：监督信号来自文本本身的结构，而不是人工标注。

### 训练的数学过程

```
输入：中心词"苹果"，目标预测周围词"吃"

第1步：查表获取向量
        苹果 → [0.2, 0.5, -0.3, ...]（随机初始化）
        吃   → [0.1, 0.4, 0.2, ...]（随机初始化）

第2步：计算点积得分
        得分 = 苹果 · 吃 = 0.2×0.1 + 0.5×0.4 + ... = 1.5
        点积越大，模型认为两个词越可能一起出现

第3步：Softmax 转换为概率
        P(吃|苹果) = exp(1.5) / Σexp(所有词的得分) = 0.02
        把得分转换成 0~1 的概率值

第4步：计算损失
        真实：苹果的周围确实有"吃" ✓
        预测概率只有 0.02，太低了！
        损失 = -log(0.02) = 3.9（损失很大）

第5步：梯度下降调整向量
        损失大 → 调整"苹果"和"吃"的向量
        → 让它们点积变大 → 下次概率更高、损失更小

重复以上步骤，直到模型收敛
```

**核心公式**：

```
预测概率：P(周围词|中心词) = exp(中心词·周围词) / Σexp(所有词的得分)
损失函数：Loss = -log P(正确的周围词|中心词)
```

### 为什么相似词向量会靠近

现在我们可以解释核心问题了：为什么"苹果"和"香蕉"的向量会变得相似？

**直观理解**

假设我们有大量句子：

```
"我 喜欢 吃 苹果"
"她 喜欢 吃 苹果"
"我 喜欢 吃 香蕉"
"他 喜欢 吃 香蕉"
```

训练过程中：
- "苹果"需要预测：喜欢、吃
- "香蕉"需要预测：喜欢、吃

它们的预测目标几乎一样！

**数学解释**

训练要求两个词都能预测出"吃"：

```
苹果·吃 要大（让"苹果→吃"的预测概率高）
香蕉·吃 要大（让"香蕉→吃"的预测概率高）
```

梯度下降会：
- 把"苹果"向量调整到与"吃"点积大的方向
- 把"香蕉"向量也调整到与"吃"点积大的方向

结果：**苹果和香蕉都被拉向了相似的方向**，它们的向量自然就变得相似了。

**这就是分布假设的实现**：

```
相似语境 → 相似预测目标 → 梯度下降拉向相似方向 → 相似向量
```

### 训练过程可视化

假设向量是 2 维的（实际通常是 100-300 维）：

```
训练前（随机初始化）：
    ↑ 维度2
    │     ● 苹果
    │ ● 香蕉
    │          ● 汽车
    │     ● 飞机
    └────────────→ 维度1
    向量随机分布，没有任何语义关系

训练中（梯度下降逐步调整）：
    ↑ 维度2
    │   ● 苹果        "苹果"和"香蕉"都要预测"吃"
    │    ● 香蕉       → 都被拉向"吃"的方向
    │          ● 汽车  "汽车"和"飞机"都要预测"开"、"快"
    │           ● 飞机 → 都被拉向这些词的方向
    └────────────→ 维度1

训练后（收敛）：
    ↑ 维度2
    │  ● 苹果 ● 香蕉    （水果聚集）
    │
    │          ● 汽车 ● 飞机  （交通工具聚集）
    └────────────→ 维度1
    相似语境的词，向量自然靠近
```

### 向量的神奇性质：类比关系

训练好的 Word2Vec 向量有一个惊人的性质：**向量运算可以表达语义关系**。

最著名的例子：

```
king - man + woman ≈ queen
国王 - 男人 + 女人 ≈ 女王
```

这意味着：
- `king - man` 得到的向量，捕捉了"皇室身份"的语义
- 加上 `woman`，就得到了女性的皇室身份：`queen`

更多例子：

```
北京 - 中国 + 日本 ≈ 东京
更大 - 大 + 小 ≈ 更小
```

这些关系不是人为设定的，而是模型自动从数据中学到的。

## 静态词向量的局限（即一词一向量）

Word2Vec 是开创性的工作，但它有一个根本问题：**一词一向量**。

### 一词多义问题

考虑"苹果"这个词：

```
"苹果很好吃"     → "苹果"是水果
"苹果发布新手机"  → "苹果"是公司
```

在 Word2Vec 中，"苹果"只有一个向量，无论出现在什么语境中都是同一个向量。这个向量可能是水果和公司的"混合体"，导致两种情况都不够精确。

### 无法理解上下文

```
"银行是存钱的地方"  → "银行"是金融机构
"我在河的银行边散步" → "银行"是河岸（这里用法不太自然，但说明问题）
```

Word2Vec 无法根据上下文调整词的向量。

### 解决方案：上下文相关的 Embedding

这就是后来 BERT 等模型要解决的问题：

```
Word2Vec：词 → 固定向量
BERT：词 + 上下文 → 动态向量
```

在 BERT 中，同一个词在不同句子中会有不同的向量。这将在下一篇文章详细介绍。

## Embedding 的直觉理解

### 向量空间是一张语义地图

可以把 Embedding 向量空间想象成一张地图：

```
┌─────────────────────────────────────────┐
│                                         │
│    ● 猫  ● 狗            ● 汽车  ● 卡车  │
│    ● 兔子                ● 飞机        │
│        （动物区）           （交通工具区）│
│                                         │
│    ● 苹果  ● 香蕉                       │
│    ● 橙子                              │
│        （水果区）                        │
│                                         │
└─────────────────────────────────────────┘
```

语义相似的词聚集在一起，形成"区域"。这就是为什么我们可以用向量距离来判断语义相似度。

### 每个维度代表什么

一个常见问题：向量的每个维度代表什么含义？比如第 1 维是情感，第 2 维是主题？

答案是：**每个维度没有明确的语义含义**。

维度是神经网络自动学习的，它们以一种人类难以解释的方式编码了语义信息。但我们知道：
- 整体向量能捕捉词的语义
- 向量之间的距离反映语义相似度
- 向量运算能表达语义关系

这就够了——我们不需要理解每个维度的含义，只需要知道怎么使用它们。

## 总结

本文解释了 Embedding 的核心原理：

**分布假设**：经常出现在相似上下文的词，语义相似

**Word2Vec 的实现**：
1. 训练目标：给定中心词，预测周围的词
2. 结果：相似语境的词 → 相似的预测目标 → 相似的向量

**向量的性质**：
- 语义相似的词，向量距离近
- 向量运算可以表达语义关系（king - man + woman ≈ queen）

**静态词向量的局限**：
- 一词一向量，无法处理一词多义
- 无法根据上下文调整
